# 웹 설치 부팅 오류 복구 안내

## 확인된 원인
업로드됐던 firmware/firmware.bin(SHA-256 dbf3c2b7ca789516aed79ca57edc5bee0287406e67a13a619f98b1c7722da882)은 앱 단독 이미지였습니다.
설치 설정은 주소 0x0부터 기록하므로 앱을 부트로더 위치에 기록했습니다.
사용자 로그의 첫 구간 주소 0x3c0f0020, 길이 0x19c7c4가 해당 앱 파일과 일치합니다.
앱의 E9 헤더와 ESP32-S3 칩 번호만으로는 통합 이미지 여부를 구별할 수 없습니다.

## 올바른 배포 파일
기존 프로젝트의 .pio/build/jc3248w535/firmware.factory.bin을 사용합니다.
- 크기: 2,841,824 bytes
- SHA-256: 5528a393c75382972da259f1c1e0d3d77217bd76423804850920480e2fa7ebda
- 0x0: bootloader.bin과 일치
- 0x8000: partitions.bin과 일치
- 0x10000: 기존 firmware.bin과 일치
- 플래시: 16MB / DIO / 80MHz
- 부트로더와 앱의 체크섬·검증 해시 정상 확인

프로젝트 파일은 수정하지 않았으며, 다시 빌드하거나 실제 USB 플래시를 수행하지 않았습니다.
이 검증은 파일 구조 검사이며, 실제 부팅·화면·터치 동작은 보드에서 확인해야 합니다.

## 교체 및 복구
1. 위 factory 파일을 저장소 firmware/firmware.bin으로 교체합니다. manifest.json의 offset 0은 유지합니다.
2. GitHub Pages 반영 후 홈페이지를 새로고침하고 "다시 확인"을 누릅니다.
3. 마끼다 배터리와 분리하고 USB 데이터 케이블로 PC에 연결합니다.
4. 필요하면 BOOT을 누른 상태에서 RESET을 짧게 누르고 BOOT을 놓아 다운로드 모드로 진입합니다. 보드의 실제 버튼 구성을 따르세요.
5. 보드 확인 체크 후 설치 버튼에서 포트를 선택합니다. 전체 삭제는 별도 선택 사항이며, 현재의 잘못된 이미지는 이 선택만 바꿔 재설치해도 해결되지 않습니다.
6. 설치 후 로그 창을 닫고 보드를 재시작해 정상 화면과 버전을 확인합니다.
7. 연결이 실패하면 다른 시리얼 모니터를 닫고 다시 시도합니다.

## 재발 방지
홈페이지는 이 보드의 통합 파일 레이아웃(부트로더 0x0, 파티션 0x8000, 앱 0x10000)을 확인합니다.
앱 단독 이미지 및 레이아웃이 다른 파일은 설치 버튼을 열지 않습니다.
이 검사는 파일의 모든 내용이나 보드 호환성을 보장하지 않으므로 릴리스 전 실기기 검증은 필요합니다.
