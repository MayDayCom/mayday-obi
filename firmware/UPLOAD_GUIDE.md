# 펌웨어 두 파일 배포

같은 빌드에서 생성된 다음 두 파일을 이 폴더에 **같은 커밋으로** 올리고, GitHub Release에도 같은 이름으로 첨부합니다.

- `firmware.bin`: 앱 단독 파일. 기기에 있는 펌웨어 업데이트 기능에서 사용합니다.
- `firmware.factory.bin`: 부트로더·파티션 테이블·앱을 포함하는 최초 설치 및 복구용 파일. 웹 USB 설치에 사용합니다.

PlatformIO 빌드 결과는 `.pio/build/jc3248w535/`에 생성됩니다. 소스의 `APP_VERSION` 한 곳에서 버전을 지정하고 빌드하면, 두 BIN 내부에 같은 버전·빌드 시각이 포함됩니다. 페이지 HTML이나 `manifest.json`의 버전을 매번 수정할 필요가 없습니다.

GitHub Release 태그는 BIN 내부의 버전과 빌드를 합쳐 `v1.10v-2026.11.11-1804` 형식으로 지정합니다. 홈페이지에 새 BIN을 배포하기 전에 해당 릴리스를 공개하고 첨부한 두 파일의 SHA-256이 원본과 일치하는지 확인하세요. 홈페이지 다운로드 버튼은 이 태그의 첨부 파일로 연결됩니다.

웹페이지는 BIN 내부의 `MAYDAY_OBI_META_V1|board=jc3248w535|version=...|build=...|END` 레코드를 읽습니다. 두 파일의 버전·빌드와 앱 바이트가 일치해야 설치할 수 있습니다. 업로드 도중 한 파일만 교체됐거나 다른 빌드 파일이 섞인 경우에는 설치를 일시 중단합니다.

표시 버전, 연결된 기기와의 비교 기준, ESP Web Tools 설치 안내가 모두 같은 BIN에서 읽은 버전을 사용합니다. USB 설치에는 검사한 파일 자체를 사용합니다.

## 기존 배포본 호환

**과거 v1.10c 배포본 호환 설명:** 예전에는 `firmware.factory.bin` 없이 통합 이미지인 `firmware.bin`만 사용했습니다. 이 구형 구성일 때만 기존 manifest의 v1.10c 정보를 사용합니다. **현재 배포본은 `firmware.bin`(앱) + `firmware.factory.bin`(통합 이미지)의 두 파일에서 버전을 자동으로 읽습니다.** 웹페이지에 표시되는 최신 배포 버전은 `manifest.json`이 아닌 BIN 내부 메타데이터를 기준으로 합니다.

새 이름의 통합 이미지가 있는데 버전 정보가 없거나 두 파일이 맞지 않으면 구형 배포본으로 우회하지 않습니다. 새 소스로 다시 빌드한 두 파일을 사용하세요.

## 설치 방식

USB 업데이트 지원 기기는 일반 BIN을 반대편 파티션에 저장하고 검증 후 새 파티션으로 자동 재부팅합니다. 웹에는 완료 및 자동 재부팅 안내를 표시합니다. 기존 버전은 기기의 복구 기능으로 선택할 수 있습니다.

최초 설치·복구는 별도로 확인한 뒤 통합 이미지를 사용합니다. 자세한 동작은 [웹 업데이트 흐름](USB_UPDATE_PROTOCOL.md)을 참고하세요.
