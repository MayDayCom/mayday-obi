# USB 반대편 파티션 업데이트

이 기능은 실행 중인 앱의 USB CDC 통신을 사용합니다. ROM 부트로더로 현재 앱을 덮어쓰는 방식이 아닙니다.

1. 기기는 현재 실행 중인 파티션과 다음 OTA 파티션, USB OTA 지원 여부를 응답합니다.
2. 웹페이지는 같은 빌드로 검증된 일반 firmware.bin의 크기, SHA-256, 버전 정보를 전송합니다.
3. 기기는 실행 중 파티션과 다른 대상만 허용합니다. Wi-Fi OTA가 진행 중이면 거절합니다.
4. 4096바이트 이하 블록의 위치와 길이를 확인하고, 반대편 파티션에 기록한 뒤 누적 수신 위치를 응답합니다.
5. SHA-256, ESP 이미지, 보드와 버전 메타데이터를 검증합니다. 성공하면 대기 중인 이미지 정보를 저장합니다.
6. 이 시점에도 부팅 대상은 현재 파티션입니다.
7. DEVICE_PROMPT=1인 기기는 저장 완료 후 기기 화면에서 **지금 재부팅 / 나중에**를 선택합니다. 웹 팝업은 완료 안내 후 닫힙니다. “지금 재부팅” 선택 때만 새 파티션을 부팅 대상으로 설정하고, 현재 버전을 반대편 버전으로 기록한 뒤 재부팅합니다.
8. “나중에” 또는 완료 팝업 닫기를 선택하면 현재 버전이 유지됩니다. 이후 기기의 기존 펌웨어 설치/복구 기능으로 대기 중인 이미지를 선택할 수 있습니다.

## 통신 명령

- MAYDAY_INFO?: 버전·USB_OTA 지원·현재/대상 파티션·대상 크기 조회
- MAYDAY_VERSION?: 이전 버전 조회 호환
- MAYDAY_OTA_BEGIN|SIZE=...|SHA256=...|APP=...|FW=...
- MAYDAY_OTA_DATA|OFFSET=...|SIZE=... 다음에 해당 길이의 바이너리 블록
- MAYDAY_OTA_END: 수신 완료 및 검증, 비활성 파티션에 보관
- MAYDAY_OTA_DEFER: 현재 버전 유지
- MAYDAY_OTA_BOOT: 명시적으로 대기 이미지로 부팅 전환
- MAYDAY_OTA_ABORT: 진행 중 수신 취소

블록 전송 중 20초 동안 데이터가 없으면 수신을 중단합니다. 부팅 대상을 바꾸지 않습니다. 덮어쓰는 쪽에 있던 이전 대기 이미지는 전송을 시작할 때부터 보존되지 않습니다.

이는 기기의 기존 수동 복구 기능과 연결한 구현입니다. 새 펌웨어의 작동 상태를 자동 진단해서 되돌리는 부트로더 자동 롤백 설정을 추가한 것은 아닙니다.

USB OTA가 없는 이전 펌웨어는 이 기능을 바로 사용할 수 없습니다. 지원 펌웨어를 기기의 Wi-Fi 업데이트 기능 또는 개발 도구로 한 번 설치해야 합니다. 웹에서 버전 응답이 없다는 이유만으로 factory 이미지를 자동 기록하지 않습니다.

## USB 수신량과 진행 표시

송신기는 CHUNK 응답이 없는 기기에 128바이트씩 보내고 매 블록의 누적 수신 확인을 기다립니다. 기기가 CHUNK를 알려주면 최대 1024바이트까지 사용합니다. 신규 펌웨어는 RX 큐 16KB 확보에 성공했을 때만 CHUNK=1024를 알리고, 실패하면 CHUNK=128로 유지합니다.

진행 화면은 준비·실제 블록 수신량·검증 단계로 구분합니다. 저장 중 버튼은 색상과 실제 disabled 상태를 함께 바꾸고 재진입을 차단합니다. 완료 확인 전에는 재부팅하거나 새 부팅 대상을 선택하지 않습니다.

DEVICE_PROMPT는 INFO 또는 READY 응답에서 확인합니다. 기존 n 빌드의 READY에만 있는 표시도 인식합니다. 기기 화면 선택이 없는 기존 USB 수신기에서는 웹 선택으로 호환합니다. 버전을 읽은 기기를 factory 설치로 자동 유도하지 않습니다.
